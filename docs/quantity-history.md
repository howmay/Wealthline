# 帳戶持倉的歷史數量

歷史補登採四步驟：**選帳戶 → 選標的 → 填日期與絕對數量 → 預覽確認**。每次只編輯一個標的；歷史數量明細預設收合，可按帳戶篩選並從單項編輯入口開啟。每日總額在桌面顯示表格、手機顯示逐日卡片。這不是交易增減或成本／報酬率引擎。補登的數量在單一持倉圖上會沿用到下一筆異動、補登或每日紀錄為止（見下方）；不修改目前帳戶、持倉或負債。

## 身分與編輯

- 同帳戶、同類型、同標的、同幣別合計所有批次；不同帳戶不合併。既有異動本來就以標的合計，沒有可靠的批次歷史，不能將合計數量套到每個批次。
- 同一日每組身分只有一列。補登到已有日期時載入該項數量，只替換選定帳戶／標的／幣別，保留其他項目與日期；從既有日的編輯入口進入則鎖定日期。預覽與套用仍比對整日原始版本，避免覆蓋同時修改。
- 日期存成 `YYYY-MM-DD`，不以 UTC 換日；新輸入禁止無效與未來日期。舊異動以使用者瀏覽器當地日期顯示，沒有保存原始時區的舊 timestamp 不聲稱能還原其原始日曆日。
- 先選帳戶，再從該帳戶目前、舊異動與過往補登出現的標的中選擇。帳戶切換會清除已選標的與草稿，避免同代號跨帳戶誤填。空帳戶可選「其他／已移除的標的」，有歷史的已刪帳戶也可選；完全沒有帳戶時提供建立帳戶提示。只有選定日期的可靠舊異動可預填數量，其他空白代表未知。可在選定帳戶加入已售出／未曾記錄的歷史標的；帳戶已完全刪除且所有歷史也不存在時，無法恢復原身分。
- 空白是未知，0 是確認當日未持有；負數、非有限數值及重複身分拒絕套用。帳戶或同帳戶持倉識別碼重複時拒絕載入，避免誤歸屬。
- 取得行情後預覽，套用後再按全域儲存才寫入 Drive。取消不改資料；清除數量恢復未知。移除單日補登會恢復原快照（若存在），可復原上次歷史修改。切換日期會捨棄未套用輸入。
- 請求期間取消或改輸入會使舊回應失效；套用會比對該日原始紀錄，拒絕覆蓋另一個已變更版本。儲存期間的新歷史編輯保留為未儲存，同時接回已成功儲存的異動中繼資料。

## 統一行情

使用既有 `/api/history` → Yahoo chart endpoint，股票與匯率都取同一來源。價格／匯率快照保存 `source`、實際代號、行情日期與值；只有代號和查詢起日送往行情服務，帳戶、數量及名稱不送出。

Yahoo 的 [Close 說明](https://ca.finance.yahoo.com/quote/EBAY/history/) 標示已調整拆股；[Adjusted Close 說明](https://help.yahoo.com/kb/SLN28256.html) 則另外包含配息調整。本功能使用 Close 與後續拆股事件還原當時每股單位價格，不使用配息調整價乘上當時實際股數。拆股資料缺漏等供應商品質仍屬來源限制；不提供報酬率或成本估算。

- 以行情回覆的交易所 IANA 時區換算日期（舊回覆無時區名稱時使用其 UTC offset）；不將現在的夏令時間 offset 套到所有過去交易日。
- 排除交易所當天尚未完成的日 K。選定日期可使用當日或往前 **7 個日曆日**內最近的已知收盤，標明實際日期；不使用未來價。若前一收盤與選定日之間跨拆股且沒有新收盤，維持未知。
- 一般外幣匯率使用 `幣別TWD=X`、相同日期政策。TWD 固定 1；現金單位價格為 1，但外幣現金仍需歷史匯率。支援的虛擬幣 USDT／USDC／BTC／ETH／SOL 使用下述 USD 換算鏈，不假設穩定幣固定等於 USD。
- 來源近 10 年以外（較早的起日會截到近 10 年）、長期停牌、查不到標的、幣別不符、沒有已完成收盤或 API 失敗，都保留數量但不估值。
- 歷史編輯只填日期與數量，沒有手填單價入口。沒有可查行情的項目保留數量，但估值未知。既有 `source: 'manual'` 歷史欄位仍能讀取，不能作為行情兜底；目前非市場資產的手填現價不刪除，也不回填歷史。
- 開啟歷史／總覽及重新查詢時，以統一來源重新估值。所有補登日共用查詢：每個代號（含匯率）只從最早補登日查一次，請求數為標的數而不是「天數 × 標的數」。一般查詢沿用瀏覽器快取（服務端設定一小時）；「重新查詢歷史行情」略過快取。供應商也可能延遲，不保證逐秒即時。顯示實際報價日期；查詢失敗時維持未知，不退回儲存價格。讀取估值不修改帳戶、數量或 Drive 紀錄。

## 單一持倉的每日價值

- 每天的數量依序取：當天以前最近的補登數量（沿用到下一筆異動、補登或每日紀錄為止，同日以補登為準）；最近一筆異動；第一筆異動之前取該異動的原數量；完全沒有異動時，每一批從自己的加入日起以目前數量計算，後來加入的批次不算進較早日期。只改手填現價的異動不算數量證據；第一筆數量異動之前，若有批次在該日之後才加入，該日維持未知。加入日不明且沒有異動或補登時為未知。每日紀錄的總額是當時依異動數量算出的，所以補登在該日停止沿用，兩邊金額一致。
- 數量跨越拆股時換算成當天的股數（例如 1 拆 4 前的 40 股顯示為 10 股），再乘上拆股事件還原的當時單位價格。
- 零持倉日期保留數量 0 與價值 0；未知數量則保留缺口，不略過日期而連成有值的線。
- 有報價代號時查 Yahoo 歷史價格與匯率，即使現在的持倉有手填價，也不把手填價格當歷史行情。現有目前行情／非市場資產現價設定保持不變。
- 歷史總額仍只在有快照或補登的日子打點。原始快照沒有完整數量明細，保留原值，不假裝可以用統一來源重建所有舊快照。手動數量日期由查詢時估值計算，與持倉圖使用相同日期／行情規則。

## 歷史總額與相容性

`history.quantityDays` 獨立保存手動數量與行情，不改寫原始 `changes` 或 `snapshots`。完整性仍以使用者確認的當日持倉清單為準，未曾留下任何紀錄的項目不可能由程式憑空得知。每日列表、總覽趨勢和歷史趨勢透過同一個 `totalPoints` 合成來源；同日手動資料優先於舊快照／即時點。原快照保留以供移除補登後復原。當天有手動紀錄時，登入時的自動快照不寫入；一般儲存仍更新當天快照（含負債與預估標記），但手動數量存在 quantityDays，估值仍以手動數量為準，隔天也能用當天記下的負債算淨資產。目前總資產與目前持倉仍顯示真實現況。今日的手動資產點使用當前負債預估；過去日期只沿用該日已記錄的負債（未知保持未知），重算資產估值時保留 liabilityEstimated 標記，不回推未記錄的負債。

任何列未知數量、缺價或缺匯率，或舊快照包含未能覆蓋且當天有餘額的帳戶，該日總資產皆顯示「資料不完整」。圖表以缺口呈現，不能用部分合計或零代替。各帳戶、類別也不偽裝完整。每日負債只沿用該日原快照；舊日期沒有負債資訊仍為未記錄，不用目前負債或攤還表回推。已知時淨資產 = 該日資產 − 當日負債，允許為負。

新增手動紀錄後使用 schema v3；已啟用自動還款／基準紀錄時保留 schema v4，不能降版。整合版本可完整讀寫 v1／v2／v3／v4，v3 升 v4 保留所有 quantityDays、原始快照及負債校正紀錄。不重建它們沒有保存的數量。舊版重新載入 v3 會拒絕解析，避免靜默遺失新增欄位；這不是跨分頁鎖，已開啟的更早客戶端仍有先前文件列出的風險。真實 Drive If-Match／CORS 尚未實測。

## 驗證與已知來源阻塞

本輪雲端環境對公開 Yahoo chart 的股票及匯率查詢都遭代理回覆 `Tunnel connection failed: 403 Forbidden`。這只能證明本環境無法連線，不代表生產來源一定失效，也不代表已驗證生產來源可用。沒有新增憑證或付費服務。網頁來源可核對價格定義；即時 API 連通性、拆股事件完整性及全商品覆蓋仍需可連線環境驗證。

本輪 102 項測試通過；lint、型別檢查、build 及 diff 檢查通過。Chromium 在 320／390／1280px 完成補登、估值、套用、編輯取消與總覽圖表操作，沒有頁面橫向溢出或執行錯誤。所有測試與手機截圖使用合成資料／模擬來源；未加入私人文件、照片或真實財務資料。檢查命令：`npm test`、`npm run lint`、`npm exec tsc -- -b`、`npm run build`、`git diff --check`。

## 漸進式補登與手機驗證

本輪由 main `75d9ebe` 建立 `fix/history-entry-mobile`，維持 v1–v4 模型與行情政策，不改動貸款計算。新日期的其他已知持倉保留為未知，不用部分金額冒充完整總額；預覽會說明完整性。返回修改保留草稿，取消／重開回到帳戶選擇；過期行情回應及已變更日程都不能覆寫資料。

原版 320px 下，700px 的每日表格需橫向捲動才找得到編輯操作，全部持倉展開又讓確認區離輸入很遠；按鈕約 38px 高。現在手機每日卡片直接呈現日期、資產、負債、淨值及操作，補登、每日列表與儲存確認的操作觸控區至少 44px。原生輸入／select 為 16px 字體，長名稱與圖例可換行，圖表提示框限制在圖內，確認視窗受動態視窗高度限制，底部加入安全區留白。

驗證使用合成長帳戶名稱、中英混合文字、大數字與同代號跨帳戶資料。128 項測試通過；Chromium 320／375／390／430px 與 1280px 桌面跑完整補登、返回修改、逐項追加、圖表及儲存確認流程。以 360px 視窗高度模擬鍵盤佔用，輸入與確認按鈕可捲動到達；這不等於真實鍵盤測試。WebKit 執行檔未安裝，因此未驗證真實 iOS Safari、原生日期選擇器外觀或裝置安全區。真實 Yahoo／Drive 限制仍適用。

## 持有期間補登

新增「持有期間」模式：帳戶 → 標的 → 開始日、選填結束／賣出日、絕對數量 → 市場估值與差異預覽。開始日包含、結束日不包含，皆指收盤持倉。例如 9/1 買入、10/2 全部賣出，9/1–10/1 有持倉，10/2 起確定為零；之後明確再買入紀錄可恢復持倉。結束留空表示持續的歷史基準，今天仍使用目前實際持倉，不據此新增或更改帳戶部位。

- 同一帳戶／標的／幣別以較晚開始的期間接手；同日起始則後新增的期間優先。接手後舊期間不恢復，舊結束日不能清除新期間。舊期間保留，可移除新期間或復原上次修改。
- 單日補登與真實數量異動在同日優先，持續到下一個期間基準或其結束日。單日未知仍是未知；純價格更新不是數量證據。期間內加減碼可拆成多個期間，或保留明確數量紀錄。
- 重疊期間、開始日後的明確數量與異動會列出差異，需勾選確認才能套用；既有原始紀錄不刪除。套用時再次核對預覽所用的期間、數量紀錄、異動和持倉，資料已變更就要求重看預覽。
- 日期字串不換日。每個標的的期間保存同一 IANA 時區，舊數量異動 timestamp 依此時區對應日期；未來日期驗證使用該時區。歷史視圖的「今天」仍沿用既有瀏覽器當地日期規則，因此跨時區使用者可能在不同時間看到最新一個已結束日。期末與開始等文字日期及歷史日期的數量不受觀看時區改寫。
- 單一持倉圖、歷史總額、總覽共用期間數量和市場估值規則；會按拆股事件調整數量，不將期間起日的股數錯乘拆股後價格。缺少行情時無法證實調整後股數／價值就顯示未知，原始期間基準數量仍保留。已知零不需要價格或匯率。其他帳戶／標的沒有可靠數量時維持未知，不推測為零。
- 期間加入 schema v5 的 `history.holdingPeriods`。讀寫 v1–v4 相容，不移轉或刪除原始日紀錄；v5 可保留所有既有資料。較早客戶端不認得 v5 時會拒絕載入。估值衍生的每日資料只存在記憶體，儲存仍只寫期間、明確日紀錄和原有歷史；沒有逐日交易／付款寫入。
- 一次輸入限近 3660 日；讀取更早的既有期間時保留原文，但只展開近 3660 日。全組合展開上限 50,000 項日資料，超限時拒絕套用並說明；每日清單分批 30 日顯示。超過行情供應商可取得範圍的價格與拆股仍需來源驗證，不代表已完整重建全歷史。

新增期間核心與 UI 回歸案例後，138 項測試通過，涵蓋日期界線、再買入、重疊／同日起始、原紀錄保留、未知、時區／DST、拆股、週末、估值一致性、資源上限、版本相容、存檔競爭、預覽取消／過期、移除及復原。使用合成資料與模擬行情；真實 Yahoo／Drive 與 iOS Safari 的驗證限制仍適用。Chromium 320／375／390／430px 的期間輸入、預覽與重疊確認流程沒有橫向溢出或執行錯誤；lint、型別檢查、build 與 diff 檢查通過。持有期間與手機補登調整維持在同一個 PR #17，未合併或手動部署。

## PR #17 審查修正

- 原始快照優先於期間推算，期間只填沒有快照的日期。明確單日補登仍可覆蓋該日呈現，移除後恢復原快照。列表與總覽使用同一規則；推算列不提供刪除原快照的按鈕，原始列的刪除確認明示來源。
- 新單日編輯只保存選定項目與當天既有紀錄，`sparse: true` 表示部分項目；查詢時補足其他標的的未知值，不把佔位 null 寫進其他期間。這種格式使用 v6，讀寫 v1–v5 保持相容，舊客戶端拒絕新版本以免誤算部分合計。原有 null 不猜用途、不自動刪除，介面提示其會中斷對應期間；使用者可逐項確認。新增期間仍保存區間，不產生逐日交易。
- 依標的建立事件索引一次，異動日期與時區 formatter 重用，查詢採二分搜尋；同日舊異動也先建立索引。相同合成基準（15 標的、300 異動、373 日）本環境展開由約 13,164 ms 降到約 11 ms；是單次本機量測，不代表所有裝置的速度。規模回歸另驗證 formatter 建立次數及寬鬆耗時上限。
- 估值依歷史證據、身分與日期建立穩定 key。目前價格、FX、負債與儲存時間不會無故清空歷史值；真正數量／標的／幣別變更會重新估值且不借用錯誤目標的舊值。主動刷新同組資料暫留上次估值並顯示狀態；完成後若來源失敗，缺值顯示未知，過期回應和卸載後回應不能回填。

本次修正後 145 項測試通過，lint（無警告）、型別檢查、build、diff 檢查通過。Chromium 320／375／390／430px 完成期間輸入、預覽、重疊阻擋／確認及取消，無溢出或執行錯誤；已查看手機截圖。同一規模在瀏覽器展開約 6–9 ms，下一幀約 9–17 ms，可繼續開啟／取消編輯。所有案例為合成資料，真實 Yahoo／Drive 並行行為與 iOS Safari 尚未實測。

## 沒有快照日期的總額比較

期間展開在行情查詢前標示數量證據是否完整；這是記憶體中的查詢資訊，不寫回資料格式。共用 `totalPoints` 只略過沒有原始紀錄、缺少數量證據、也沒有明確未知的自動推算日；這類日期不論行情如何總額都無法計算，所以估值讀取中或行情失敗時同樣略過，讓總覽與歷史的圖表、比較和每日列表一致。介面顯示略過日數及原因，不將省略解讀為零；原始快照仍優先，個別持倉走勢不受總額篩選影響。

明確單日補登、刻意／舊有未知及其期間延續、數量證據完整但真正缺價／缺匯率（含拆股資料不可得）、已知零，都保留。不能只用 `periodDerived && total === null` 判斷，因為缺少行情也可能令已知數量在估值時變成未知。比較使用實際前一個保留的日期；只相隔一天才標示「昨天」。有紀錄但資料不完整時顯示「無法比較」，不再誤稱尚無更早紀錄。

### 虛擬幣歷史匯率

支援幣別共用「虛擬幣/USD × USD/TWD」：查詢 Yahoo 的 `USDT-USD`（依幣別替換）與 `TWD=X`，不再查詢不存在的 `USDTTWD=X`。補登預覽、每日總額、總覽與單一持倉歷史共用換算；目前匯率不作為歷史替代。例如 7 USDT、歷史價 0.98 USD、匯率 32 TWD，估值為 219.52 TWD。

每段各自取當日或前七日內的已完成行情，拒絕未來價、過期價、幣別或代號不符。週末兩段的行情日可以不同，預覽分別顯示來源、代號、日期和值。任一段失敗保持未知並指出是哪一段；API 將來源異常回覆為 `502 provider_error`（不快取），與 `404 not_found` 區分。保留零餘額與未知數量不查價的規則。

套用含換算鏈的單日紀錄時使用 v7，儲存兩段來源及乘積，讀入時驗證日期、代號與乘積；其他編輯及非同步儲存不降回舊版。v1–v6 仍可讀取，既有數量與其他欄位保留。舊版客戶端不支援 v7，應更新預覽版本後再讀取，不能刪除資料檔處理。

回歸測試涵蓋五種幣別、脫鉤、缺少任一段、來源異常、週末異日行情、未來／過期行情、換算鏈 round-trip、重新查詢失敗與既有非虛擬幣路徑。Chromium 合成資料於 320／375／390／430 px 檢查預覽、套用及無橫向溢出。此環境對真實 Yahoo API 的網路代理限制仍如前述；測試行情是合成資料，未驗證真實 iOS Safari、Google Drive 或 Yahoo 生產連線。

### 日期列編輯與歷史頁分區

既有單日紀錄只有一項時，「編輯數量」直接帶入帳戶、標的、固定日期與數量；多項時只列該日實際紀錄（包括未知、零及已移除帳戶），不預選，也不混入目前才有的持倉。可返回改選其他項目，預覽後套用；其他項目、日期及目前持倉保持不變，項目順序不因套用而改變。沒有單日數量的原始快照／期間日期使用「補登數量」入口，保留新增單日與期間流程。套用後仍須使用全域「儲存變更」。編輯期間停用其他日期列入口，避免無提示切換而丟失草稿；取消或 Escape 關閉後，重開從既有紀錄開始。

歷史頁分為標題、資料與行情、歷史持倉數量及原有統計／圖表區。來源區將紀錄優先規則與市場行情說明分欄，手機改單欄；查詢按鈕與說明各自排版。未知數量、行情失敗及缺口警示保持可見。

### 以完整數量基底回補差異（v8）

「沿用持倉回補差異」是明確的單日完整清單操作，可從較晚日期回補較早日期。例如選 10/09 已填數量清單作來源，回補 09/01，A 原數量 100 改填目的日絕對數量 300，介面顯示差異 +200；B–E 自動帶入原數量，不需重新填寫。不是輸入增減交易，不自動換算拆股前數量；使用者須確認目的日的實際絕對數量。來源日與目前持倉不變，價格與匯率重新取得目的日可用市場行情，不複製來源價格、匯率、手填價或拆股基準。

可用來源僅限目前完整持倉（明示包含未儲存修改）或具有 `inventory` 完整範圍標記的歷史清單。總額-only 快照不列為來源；稀疏／未驗證清單即使每個已列項目都有數量、來源日沒有快照，也不可作完整基底。介面顯示原因但不提供勾選升格路徑，核心產生／套用回補也會阻擋。不能用 all-time catalog 補 0 或猜測範圍。可靠來源若含未知／無效數量仍阻擋；明確 0 與完整範圍內的空帳戶可保留。

預覽列出來源日、目的日、完整範圍、來源與目的數量差異、目的日原數量與將移除的項目；原快照有而回補不含的帳戶也單列警示。目的日已有數量或原快照時，最後確認明示取代目的日估值。目的日原有期間推算另列基準日期與數量，明示僅覆寫目的日，後續期間不變。來源或目的日資料在選取／預覽後改變時要求重新預覽；取消、Escape、返回、切換來源會正確失效舊請求或確認。套用後仍需全域儲存；可復原上次歷史修改。

必要的新語義存在 `quantityDays[].inventory`：保存帳戶範圍（含空帳戶）與來源種類／日期；表示**使用者確認的目的日完整資產清單**。不設 `sparse`，數量不可未知。查詢完整回補日不再加入 all-time catalog 的缺項；單一持倉圖對該完整日未列出的項目視為明確未持有，與總覽／每日總額一致。完整回補只覆寫目的日，不加入期間延續事件，也不向其他日期沿用；既有期間、稀疏單日及舊未知紀錄保留原語義。負債不從來源日複製，沿用目的日原紀錄；未記錄仍未知。原始總額快照保留，移除回補可恢復原快照。

套用完整回補升為 v8，以免舊客戶端忽略完整範圍而誤算。讀取 v1–v7 相容，不自動遷移、宣稱舊清單完整或刪除舊 null；其原有保守缺項規則不變。一般編輯、期間新增與非同步儲存均不降版。v8 檔案需更新後的客戶端，不應刪除 Drive 資料處理版本不相容。
