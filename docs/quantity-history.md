# 帳戶持倉的歷史數量

首頁以時間線滑桿及日期選單切換快照，總資產、負債、淨資產與帳戶／配置同步更新；舊 `/history` 連結導回首頁。支援按帳戶、持倉、日曆日期補登當日的**絕對數量**。這不是交易增減或成本／報酬率引擎。補登的數量在單一持倉圖上會沿用到下一筆異動、補登或每日紀錄為止（見下方）；不修改目前帳戶、持倉或負債。

## 身分與編輯

- 同帳戶、同類型、同標的、同幣別合計所有批次；不同帳戶不合併。既有異動本來就以標的合計，沒有可靠的批次歷史，不能將合計數量套到每個批次。
- 同一日每組身分只有一列。新增遇到已補登日期時要求使用該日的編輯入口；編輯不改日期。可另新增另一日期，原日期保留。
- 日期存成 `YYYY-MM-DD`，不以 UTC 換日；新輸入禁止無效與未來日期。舊異動以使用者瀏覽器當地日期顯示，沒有保存原始時區的舊 timestamp 不聲稱能還原其原始日曆日。
- 初次補登列出目前、舊異動與過往補登曾出現的持倉。只有選定日期的可靠舊異動可預填數量，其他空白代表未知。可在現有帳戶加入已售出／未曾記錄的歷史標的；帳戶已完全刪除且所有歷史也不存在時，無法恢復原身分。
- 空白是未知，0 是確認當日未持有；負數、非有限數值及重複身分拒絕套用。帳戶或同帳戶持倉識別碼重複時拒絕載入，避免誤歸屬。
- 在彈窗按一次「儲存這天」，自動取得行情並寫入 Drive；失敗保留草稿及重試入口。取消不改資料；清除數量恢復未知。移除單日補登會恢復原快照（若存在），可復原上次歷史修改。切換日期會捨棄未儲存輸入。
- 請求期間取消或改輸入會使舊回應失效；套用會比對該日原始紀錄，拒絕覆蓋另一個已變更版本。儲存期間的新歷史編輯保留為未儲存，同時接回已成功儲存的異動中繼資料。

## 統一行情

使用既有 `/api/history` → Yahoo chart endpoint，股票與匯率都取同一來源。價格／匯率快照保存 `source`、實際代號、行情日期與值；只有代號和查詢起日送往行情服務，帳戶、數量及名稱不送出。

Yahoo 的 [Close 說明](https://ca.finance.yahoo.com/quote/EBAY/history/) 標示已調整拆股；[Adjusted Close 說明](https://help.yahoo.com/kb/SLN28256.html) 則另外包含配息調整。本功能使用 Close 與後續拆股事件還原當時每股單位價格，不使用配息調整價乘上當時實際股數。拆股資料缺漏等供應商品質仍屬來源限制；不提供報酬率或成本估算。

- 以行情回覆的交易所 IANA 時區換算日期（舊回覆無時區名稱時使用其 UTC offset）；不將現在的夏令時間 offset 套到所有過去交易日。
- 排除交易所當天尚未完成的日 K。選定日期可使用當日或往前 **7 個日曆日**內最近的已知收盤，標明實際日期；不使用未來價。若前一收盤與選定日之間跨拆股且沒有新收盤，維持未知。
- 匯率使用 `幣別TWD=X`、相同日期政策。TWD 固定 1；現金單位價格為 1，但外幣現金仍需歷史匯率。不把 USDT／USDC 等穩定幣假設成 USD，沒有對應歷史匯率就顯示未知。
- 來源近 10 年以外（較早的起日會截到近 10 年）、長期停牌、查不到標的、幣別不符、沒有已完成收盤或 API 失敗，都保留數量但不估值。
- 歷史編輯只填日期與數量，沒有手填單價入口。沒有可查行情的項目保留數量，但估值未知。既有 `source: 'manual'` 歷史欄位仍能讀取，不能作為行情兜底；目前非市場資產的手填現價不刪除，也不回填歷史。
- 開啟歷史／總覽及重新查詢時，以統一來源重新估值。所有補登日共用查詢：每個代號（含匯率）只從最早補登日查一次，請求數為標的數而不是「天數 × 標的數」。一般查詢沿用瀏覽器快取（服務端設定一小時）；「重新查詢歷史行情」略過快取。供應商也可能延遲，不保證逐秒即時。顯示實際報價日期；查詢失敗時維持未知，不退回儲存價格。讀取估值不修改帳戶、數量或 Drive 紀錄。

## 單一持倉的每日價值

- 每天的數量依序取：當天以前最近的補登數量（沿用到下一筆異動、補登或每日紀錄為止，同日以補登為準）；最近一筆異動；第一筆異動之前取該異動的原數量；完全沒有異動時，每一批從自己的加入日起以目前數量計算，後來加入的批次不算進較早日期。只改手填現價的異動不算數量證據；第一筆數量異動之前，若有批次在該日之後才加入，該日維持未知。加入日不明且沒有異動或補登時為未知。每日紀錄的總額是當時依異動數量算出的，所以補登在該日停止沿用，兩邊金額一致。
- 數量跨越拆股時換算成當天的股數（例如 1 拆 4 前的 40 股顯示為 10 股），再乘上拆股事件還原的當時單位價格。
- 零持倉日期保留數量 0 與價值 0；未知數量則保留缺口，不略過日期而連成有值的線。
- 有報價代號時查 Yahoo 歷史價格與匯率，即使現在的持倉有手填價，也不把手填價格當歷史行情。現有目前行情／非市場資產現價設定保持不變。
- 歷史總額仍只在有快照或補登的日子打點。原始快照沒有完整數量明細，保留原值，不假裝可以用統一來源重建所有舊快照。手動數量日期由查詢時估值計算，與持倉圖使用相同日期／行情規則。

## 歷史總額與相容性

`history.quantityDays` 獨立保存手動數量與行情，不改寫原始 `changes` 或 `snapshots`。完整性仍以使用者確認的當日持倉清單為準，未曾留下任何紀錄的項目不可能由程式憑空得知。首頁快照及趨勢透過同一個 `totalPoints` 合成來源；同日手動資料優先於舊快照／即時點。原快照保留以供移除補登後復原。當天有手動紀錄時，登入時的自動快照不寫入；一般儲存仍更新當天快照（含負債與預估標記），但手動數量存在 quantityDays，估值仍以手動數量為準，隔天也能用當天記下的負債算淨資產。目前總資產與目前持倉仍顯示真實現況。今日的手動資產點使用當前負債預估；過去日期沿用該日已記錄的負債（未記錄以 0 計，明確缺匯率的 null 保持未知），重算資產估值時保留 liabilityEstimated 標記，不回推未記錄的負債。

任何列未知數量、缺價或缺匯率，或舊快照包含未能覆蓋且當天有餘額的帳戶，該日總資產皆顯示「資料不完整」。圖表以缺口呈現，不能用部分合計或零代替。各帳戶、類別也不偽裝完整。每日負債只沿用該日原快照；舊日期未記錄負債以 0 計；明確無法換算則維持未知，不用目前負債或攤還表回推。已知時淨資產 = 該日資產 − 當日負債，允許為負。

新增手動紀錄後使用 schema v3；已啟用自動還款／基準紀錄時保留 schema v4，不能降版。整合版本可完整讀寫 v1／v2／v3／v4，v3 升 v4 保留所有 quantityDays、原始快照及負債校正紀錄。不重建它們沒有保存的數量。舊版重新載入 v3 會拒絕解析，避免靜默遺失新增欄位；這不是跨分頁鎖，已開啟的更早客戶端仍有先前文件列出的風險。真實 Drive If-Match／CORS 尚未實測。

## 驗證與已知來源阻塞

本輪雲端環境對公開 Yahoo chart 的股票及匯率查詢都遭代理回覆 `Tunnel connection failed: 403 Forbidden`。這只能證明本環境無法連線，不代表生產來源一定失效，也不代表已驗證生產來源可用。沒有新增憑證或付費服務。網頁來源可核對價格定義；即時 API 連通性、拆股事件完整性及全商品覆蓋仍需可連線環境驗證。

先前版本 102 項測試通過；lint、型別檢查、build 及 diff 檢查通過。Chromium 在 320／390／1280px 完成補登、估值、套用、編輯取消與總覽圖表操作，沒有頁面橫向溢出或執行錯誤。所有測試與手機截圖使用合成資料／模擬來源；未加入私人文件、照片或真實財務資料。檢查命令：`npm test`、`npm run lint`、`npm exec tsc -- -b`、`npm run build`、`git diff --check`。

首頁快照整合：123 項測試、lint、型別檢查、build 與 diff 檢查通過。以合成資料在桌面及 390px 瀏覽器預覽確認日期切換、彈窗編輯、單次儲存與取消；390px 沒有水平溢出。Drive 寫入失敗後草稿保留及重試使用模擬回應驗證，未操作真實 Drive 或部署正式站。
