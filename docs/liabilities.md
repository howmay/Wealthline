# 負債管理與貸款試算

## 行為與資料格式

負債獨立於資產帳戶，以 `liabilities` 陣列儲存。每筆包含 `id`、名稱、類型、幣別及非負的 `balance`；0 代表目前無欠款。類型為房貸、信貸、信用卡與其他。

新增貸款預設本息平均攤還，主流程填「原始貸款總額、年利率（百分比）、總期數、第一期還款日」，不要求目前期別、已繳或剩餘期數。第一期還款日是首次應繳款日，不是撥款日。可改成本金平均攤還。信用卡、寬限期及不規則還款使用手動模式；舊有剩餘本金模式保留於進階選項，不從舊餘額反推本金或日期。

按期模式的 `balance` 是不隨日期改寫的基準本金，`remainingInstallments` 為該基準的完整期數（原始貸款就是總期數）；沿用欄位以保存舊資料語義。`schedule` 保存 `source`（original/correction）、`baseDate`、`firstDueDate`、`monthlyDay` 和 IANA `timeZone`。original 的 baseDate 為第一期前一天，僅作運算基準，不表示撥款日；首期前顯示完整本金。correction 的本金則是基準日結束時餘額，該日之前無法估算。

每月日期預設取自第一期日期，可於進階覆寫 1–31 日；第一期須與該月錨點一致。29／30／31 日遇短月取月底，後續月份仍使用原錨點。貸款時區預設瀏覽器時區並明示，儲存後跨裝置一致；按該時區的到期日（包含當日）推算已到期期數。開站、重整、離線後重開、兩裝置及寫入重試都只是重新計算，不儲存逐期付款事件，也不對基準重複扣減。開啟頁面每 30 秒及頁面喚醒時更新顯示。

修改名稱／備註不重設基準；變更本金、利率、期數、幣別、日期或時區須用「校正餘額／重設基準」，核對本金、填原因並勾選確認。預填的當前餘額仍是估算；舊基準存入 `basisHistory`（時間、原因、幣別、本金、利率、期數、方式及日程）。新利率只從新基準起算；過去快照不重算。停用估算也在同一校正流程確認餘額，避免跳回原始本金。已清償可填 0，本金為 0 時不再扣減；如保留按期模式，基準期數仍要求 1–1200，但衍生剩餘期數為 0。

既有 `paymentAmount`、`totalInstallments`、`paidInstallments` 手填值仍可讀取、保留並顯示，不再要求重複輸入。不替舊資料選擇攤還方式或由總期數推定剩餘期數；未指定方式時不試算。每期應付不等於實際未償本金。此功能沒有自動扣款、銀行串接、提醒或收據匯入。

## 試算公式與限制

依[土地銀行還款試算說明](https://www.landbank.com.tw/Calculate/Repayment)：設目前本金為 P、剩餘月數為 n、月利率 r = 年利率百分比 / 1200。本息平均攤還每月應付 A = P × r / (1 − (1+r)^−n)，當 r = 0 時為 P/n。本金平均攤還每月本金 P/n，利息為期初餘額 × r，應付隨本金餘額降低；0% 時不變。介面分開呈現固定月付與首末期應付。

假設每月繳款、利率固定、沒有寬限期、提前還款及費用。銀行按日計息、利率調整及捨入方式可能不同，因此僅供估算。試算顯示每期本金、利息、應付、期末本金與完整基準計畫總利息。自動模式只將到期本金計入預估已償本金，不把利息扣成本金；當前估計欠款計入預估負債與淨資產，明示為預估，不代表銀行實際餘額或已付款，也不減少任何現金資產。手動模式保持原行為。

期數限 1–1200 整數（最多 100 年），每頁 12 期。運算不逐期捨入，使用 log1p/expm1 改善極小利率與長期數的穩定性，補償加總利息並在最後一期結清剩餘本金。顯示小數 2 位，各欄獨立四捨五入，可能有顯示尾差；超出有限數值範圍時拒絕套用試算條件。

總負債依既有匯率換算為 TWD；淨資產 = 總資產 − 總負債，允許為負。任何非零資產或負債缺少有效匯率時，不呈現不完整的淨資產。已清償的零餘額不因缺少匯率變成未知負債。

表單套用只更新記憶體，仍需「儲存變更」。刪除需明確確認；確認視窗可復原新增、修改或刪除的負債。取消表單不改資料；取消儲存確認保留已套用但未儲存的修改。

## 相容與歷史

- 可載入 v1 JSON，負債不存在時視為尚未記錄。
- 完整讀取 v1／v2／v3／v4。僅手動負債仍使用 v2，只有持倉歷史則維持 v3；啟用日程／基準紀錄後升為 v4。v4 同時保存 quantityDays、貸款日程、基準紀錄與全部既有歷史；停用／刪除貸款、編輯數量或非同步儲存亦不降版。讀取本身不改寫遠端檔案。舊 v1／v2／v3 客戶端拒絕不支援的較新版本，避免忽略欄位後覆存。
- 版本欄位不是跨客戶端的寫入鎖，不能保證已開啟的舊分頁不覆寫資料。已載入 v1 的分頁仍可嘗試儲存：包含條件寫入修復的版本依賴 Drive 的 `If-Match`（真實原子性仍待驗證）；更早的無條件寫入版本仍可能覆蓋 v2 資料。
- v2／v3／v4 的 `liabilities` 必須是陣列，識別碼不得重複；數值必須有限且非負。期數必須是有效整數，已繳期數不得超過已知總期數；日期必須有效。
- 既有 `history.changes` 保持資產口徑；負債新增 `history.liabilityChanges`，保存完整修改前後狀態，包含名稱、幣別與選填欄位。
- 快照 `total`、帳戶及類別仍只代表資產，原資產圖不扣負債。另新增 `liabilityTotal` 與 `netWorth`；欄位不存在表示「未記錄」，null 表示「無法換算」。不重建未知的過去負債。按期負債快照依快照的 at 時間及貸款時區計算，另記 `liabilityEstimated: true`，負債／淨資產介面顯示預估；不生成假付款異動。
- 僅有負債也能記錄每日快照；刪除最後一筆負債會記錄為 0，避免歷史持續沿用舊餘額。
- 資產試算表匯入不修改負債。沿用既有 Drive 條件寫入與同步鎖，儲存等待期間的新負債修改／刪除仍保留且維持 dirty。

## 驗證

所有 fixture 均為自行建立的合成資料，不含個人財務文件的金額或識別資訊。

```sh
npm test
npm run lint
npm exec tsc -- -b
npm run build
git diff --check
```

回歸涵蓋負債新增、編輯、取消、刪除、復原、零餘額、負淨資產、多幣別、缺失匯率、v1→v2、舊快照未知值、獨立負債異動、刪除最後一筆，以及每日快照寫入期間修改負債。另涵蓋兩種攤還公式、零利率、零本金、單期、1200 期、極小利率、數值溢位、分頁與舊手填資料保留。React 操作測試使用 jsdom；另以本機 Chromium 及模擬 Drive 檢查手機／桌面版面，不連接 Google 帳戶。

新增回歸涵蓋月底錨點、閏年／世紀年、含到期日、台北與洛杉磯 DST、不同裝置時區、長期未登入補算、重複計算不變性、手動校正與停用、錯誤日期、v4 及非同步保存不降版。
